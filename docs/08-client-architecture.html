What L7 owns

L7 is a terminal layer: it reads, it never writes to the corpus, and it holds no authority over legal content. Its job is to present grounded material truthfully, to keep working when the network does not, and to be usable by someone who cannot comfortably read.

Four surfaces, one contract

They differ in audience, rendering strategy and failure tolerance — but all four speak only IPublicAPI and ISync, so a change in the backend breaks a generated client at build time rather than a user at runtime.

§3Offline
architecture

The pack in the pocket

QA-9 says full statutory lookup at zero connectivity. That is not a caching requirement — it is a distribution requirement, and it produces the most consequential design in the client: a signed, versioned, transactionally-updated copy of Pakistani statute law that the app treats as authoritative rather than as a cache.

3.1Content classes decide the read path

Everything the client can read falls into one of three classes, and the class — not the network state — determines where a read goes first.

ClassContentRead pathOffline behaviour
Pack-authoritativeStatutory text, provision tree, cross-references, definitions, precomputed explainers, glossary, procedure guides, limitation and fee tablesLocal first, always. Never revalidated per read — the pack is signed, so its content is as trustworthy as the server’sFully available. This is the majority of citizen usage.
Network-preferredSearch ranking, as-at-date versions outside the pack window, provisions in an uninstalled tierNetwork when available; degraded local equivalent when not, explicitly labelledReduced quality, announced. Offline search is lexical plus glossary rather than server-reranked.
Answer-pack-servedGrounded answers to questions in the head of the distribution — the offline answer tier (§3.4)Local question index first; network only on a missAvailable with full citations and provenance, showing the canonical question matched.
Network-requiredNovel questions that miss the answer pack, precedent and citator, judgment text, document draftingNetwork only. INV-2 forbids a client-side substituteUnavailable, with a specific explanation and an offline alternative offered — never a spinner, never a silent failure.

Why judgments are not in the pack

Precedent is a graph query over hundreds of thousands of paragraphs plus treatment classification. Shipping it would multiply pack size by an order of magnitude and still give a worse answer than the server. It is declared network-required and the UI says so plainly. Choosing what not to ship offline is as much a part of this design as choosing what to ship — and §3.4 applies the same reasoning in the other direction, shipping answers because they are small and verified, rather than a generator because it is fashionable.

3.2Pack anatomy and tiers

3.3Patch format

Deltas are row-level operations, not a binary diff of the database file. A page-level diff would be fragile across SQLite versions and vacuum states, and would defeat resumability.

patch v17 → v18
  header    from_version, to_version, schema_version, built_at, sha256, ed25519_sig
  ops[]     UPSERT instrument   {id, …}
            UPSERT provision    {id, path, label, heading, status}
            UPSERT provision_text {provision_id, text_en, text_ur, validity}
            DELETE provision    {id}          only when an instrument is withdrawn
            UPSERT explainer    {provision_id, plain_en, plain_ur}
  post[]    REINDEX fts(scope)                 partial, scoped to touched instruments
            REVEC   vec(scope)                 only if the semantic tier is installed

Application is one SQLite transaction per patch, chained. Signature verified before
the transaction opens; integrity hash compared after it commits, before the version
pointer moves. Any failure rolls back and the version pointer never advances.

Chain length is capped at twelve. A device that has been offline for months takes a full re-download rather than replaying a long chain — simpler to reason about, and usually smaller.

3.4Offline grounded answers — RAG without a model on the device

“Offline RAG” sounds like it requires an on-device generator. Priced honestly it does not, and it should not: a 1B parameter model quantised to four bits is roughly 800 MB, needs several seconds of prefill for a 2,000-token context on a mid-tier phone, and would still reason about Pakistani law worse than the server did. Shipping it would multiply the install size by six to lower the answer quality.

The better move follows from something the architecture already guarantees: our answers are strictly grounded and therefore reusable. An answer that was generated against verified provisions, had its citations rendered from the database, and passed the entailment verifier is a durable artefact. So we ship the answers, not the generator.

Coverage is a measured metric, not a claim. It is reported per language and per stratum on the golden set, and regression blocks a pack release.

The invalidation rule that makes this safe

Every stored answer records the provisions it cites and the corpus version it was generated against. A pack patch that amends any cited provision carries an INVALIDATE operation for every dependent answer, so the answer is removed rather than served stale. Without that rule the answer tier would slowly become a cache of law that no longer exists — which is the failure mode this entire product is built to avoid.

3.5Two sync engines, because there are two trust models

The corpus flows one way and is signed; user data flows both ways and must merge. Trying to serve both with one mechanism produces either a corpus that a client can corrupt or user data that cannot be edited offline. They are separate engines with separate storage and separate failure behaviour.

§4Navigation
& IA

Routes are provision identities

INV-4 has a direct consequence for navigation: every durable location in the product is addressed by a provision, instrument or judgment identity — never by a chunk, a search-result index, or a session-scoped token. A bookmark taken today resolves after five re-indexes.

4.1Deep links and the public URL contract

app + web share one URL grammar

  /law/punjab/act-2019-12/s-7/cl-b            clause-level deep link
  /precedent/provision/fed:act-1860-45:s-302  citator for a provision

rules

  • Web and app resolve identical paths; an Android App Link opens the app

    selects a version, and lang, which selects presentation.

5.2Screen-state taxonomy

Every screen resolves to exactly one of eight states. The shell renders the state; the notifier chooses it. There is no ninth state and no ad-hoc inline spinner.

sealed ScreenState
  Loading      skeleton matched to the eventual layout, never a centred spinner
  Ready        content
  Empty        a valid query with no matches — distinct from Abstained
  Abstained    the gate declined — only reachable on generated surfaces
  Offline      network-required content on a device with no network
  Stale        served from a pack older than the currency threshold
  Degraded     served by a reduced path (lexical-only search, cached answer)
  Error        an actual fault — the only state that offers “retry”

Rule: Abstained, Offline, Stale and Degraded are outcomes, not faults. None of
them may borrow error styling, an error icon, or a retry affordance.
§6Bilingual
& bidi

Two scripts, one sentence

QA-6 asks for bilingual equity, and most implementations deliver it by translating the interface and stopping. The hard part is that a single Urdu sentence about Pakistani law contains left-to-right statutory identifiers, and getting that wrong does not look like a typography bug — it looks like a citation to a different section.

6.1Three independent axes

Language is not one setting. Conflating these is the root cause of most bilingual legal UI failures.

AxisValuesControlsIndependent because
UI languageen · urChrome, labels, navigation, layout directionA user may want Urdu chrome around English statutory text — and frequently does, because the statute is English.
Content languageen · ur · bothExplanations, answers, judgment summaries. Never the statutory text itselfStatutory text is shown verbatim in its enacted language always; only explanation is translated (document 01, ADR-4).
Input scriptlatin · arabic · roman-urduQuery normalisation, glossary alias lookup, keyboard hintDetected per keystroke, not chosen. A user with Urdu chrome will still type talaq on a Latin keyboard.

6.2Two type scales, selected by script

Nastaliq is a sloped, deeply cascading script: a line of Urdu occupies far more vertical space than a line of Latin at the same nominal size, its descenders collide at Latin line-heights, and its optical size runs small. A single scale cannot serve both, and a scale chosen by locale breaks on the mixed run this section is about. The scale is therefore chosen per run, by script.

Statutory body16 / 1.6219 / 2.05Urdu is set larger and much looser; the two must share a baseline grid so a mixed line does not jitter
Provision heading17 / 1.35 · 60020 / 1.8 · 400Nastaliq has no usable bold; emphasis comes from size and colour, never synthetic weight
Answer prose16 / 1.619 / 2.0—
Citation chip13 / 1.2 · mono13 / 1.2 · monoAlways Latin metrics — a citation is never set in Nastaliq
Caption / meta13 / 1.515 / 1.9—

6.3What mirrors and what does not

Mirrors under RTLNever mirrors
Layout axis (start/end, never left/right) · navigation and back affordances · list chevrons · progress and stepper direction · provision clause indentation · drawer side · slider direction Source PDF page previews · the amendment timeline, which is chronological and always runs left to right · numerals within a citation · the curation console’s source-versus-parse comparison · media transport controls · anything reproducing a printed legal document

The amendment timeline is the instructive case: it is a chronological axis, not a reading order. Mirroring it in Urdu would put 2026 on the left and 1860 on the right, which reads as a claim about time rather than about language. Directionality follows the semantics of the axis, not the direction of the surrounding text.

6.4Roman Urdu at the client edge

input       "mje talaq k baad bachon ki custody chahiye"
detect      latin script + roman-urdu classifier → script = roman-urdu
normalise   consonant folding (k/ke/kay → ke) · vowel elision · digraph
            variants (kh/x, q/k) · repeated-letter collapse
expand      glossary alias lookup, client-side against the pack:
              talaq   → divorce, dissolution of marriage
              custody → hizanat, guardianship, custody of minors
send        original text + detected script + expanded concept IDs
            the server re-does this authoritatively; the client copy exists so that
            offline search works and so the keyboard hint is right

Normalisation is deliberately duplicated on both sides. The client copy is a convenience that must never disagree with the server; both read the same versioned glossary artefact, and a mismatch in glossary version is a client warning, not a silent divergence.

Where voice runs, and why it matters for privacy

Speech-to-text runs on-device where the platform provides an offline Urdu model, and falls back to a server call otherwise. That fallback is disclosed at the moment of use, and it is disabled entirely in anonymous mode — a voice query that leaves the device is a recording of someone describing a legal problem aloud, which is precisely the data QA-12 exists to protect. Text-to-speech is always on-device.

§8State, data
& security

State, sources and secrets

8.1State management

Riverpod with code generation, and one rule that matters more than the choice of library: a notifier exposes an immutable view state and nothing else. No widget reads a repository, no repository holds UI state, and no notifier persists anything.

unidirectional, per screen
  intent      user action → Notifier method
  work        Notifier → UseCase → Repository → (LocalPack | Api)
  state       Repository returns entities; UseCase applies policy;
              Notifier emits AsyncValue<ViewState>
  render      Widget rebuilds from ViewState — a pure function of state

forbidden
  • a widget that computes an in-force date, formats a citation, or
    decides whether something is repealed
  • a notifier that imports package:sqlite3 or package:http
  • a repository that returns a DTO, a nullable network type, or a Future
    that the caller must remember to catch

8.2Anonymous mode is a different object graph

Document 01 requires that anonymous mode be enforced at session scope rather than checked at call sites. A boolean consulted in twenty places will eventually be missed in the twenty-first. Instead the dependency container is rebuilt with different concrete implementations, and the code that could write is simply not present in the graph.

§10Web
& SEO

The web tier and the distribution flywheel

ADR-9 in document 01 makes public statute pages an architectural decision rather than a marketing one. Pakistan Code is effectively unindexed; a crawlable, fast, citable page for every provision is the cheapest acquisition channel available to this project by an order of magnitude.

10.1SEO architecture

  • Internal links come from the cross-reference graph. Section 302 links to 299, 304 and 311 because the corpus says it does. The link structure is generated from data rather than authored, which makes it complete, correct, and free.
  • Structured data — Legislation JSON-LD per provision with jurisdiction, enactment date, and status; BreadcrumbList for the instrument tree.
  • Sitemap index partitioned by jurisdiction, regenerated on corpus publish. Roughly 60,000 URLs at launch and growing.
  • hreflang pairs for the English and Urdu renderings of the same provision, with a shared canonical.
  • No generated content on public pages at launch. Authoritative statutory text and verified explainers only, and explainers are labelled as machine-generated. Publishing unreviewed AI prose at scale under our own domain is a reputational and legal risk we take deliberately, later, or not at all.

CDR-8Type scale selected per run by script, not by localeA single sentence contains both scripts; a locale-selected scale breaks exactly on the mixed run that matters mostEvery text render walks runs rather than taking a single style

B.1What this document does not decide

Visual identity, illustration, iconography and motion choreography belong to document 12, Design System & UX. The token structure and the bilingual type scales are fixed here because they are architectural — a locale-selected scale would break the mixed-run guarantee — but the specific hues, spacing ramp and icon set are not. Screen-by-screen interaction specifications for drafting and procedure belong to document 06, which owns those domains.

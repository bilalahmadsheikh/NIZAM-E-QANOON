## Actual model and failure stage

- `document`, `page`, and `text_block` preserve source pages, immutable block text/coordinates, and per-document `reading_order` (`0002_extraction.sql`). `source_observation` and blob SHA identify the PDF observation. `instrument` identifies a legal expression; `source_start_block_id`/`source_end_block_id`, `instrument_expression_manifest`, and `instrument_expression_span` handle separate or discontiguous instruments within one PDF (`0004`, `0040`, `0049`).
- `provision` stores `kind`, printed `label`, heading, `parent_id`, `path` (ltree), ordinal, page range, and `first_block`. `provision_version` stores the operative text. Active `block_assignment_set` plus `provision_block` assigns every source block a body, contents, footnote, heading, schedule-row or other role (`0004`, `0006`, `0012`). `instrument_toc_entry` stores printed contents, separate from operative provisions (`0011`). `provision_ancestor` is derived from the real parent graph, not a source of truth (`0018`, `0027`).
- The pure parser in `nizam/corpus/segment.py` subdivides blocks, classifies openings with `RULES`/`classify`, infers parents via its stack in `segment`, then chooses/demotes repeated section/article siblings in the collision pass. `_apply_source_reparents` handles exact source-reviewed overrides *after* collision handling. `nizam/workers/segment.py:build` serializes its tree; `nizam/storage/legal_write.py` writes the nodes, parent IDs, paths, block ledger, TOC links and S7 proposals in one transaction. `segmentation_structural_candidate` and append-only `segmentation_structural_adjudication` (`0035`, `0036`) hold candidate/reviewer decisions. Release views fail closed on unresolved structural/TOC issues (`0043`).
- An erroneous parent can first arise when `classify` misses a qualifier, or when `segment` unwinds its stack to a fixed section depth. A legitimate provision can then lose its section kind in the **later** repeated-sibling collision pass (`segment.py`, near the `repeated_label_decisions` loop). The persisted writer copies that derived decision; it is not the origin of doc 118's bad parent.

## Root causes and bounded correction proposed

1. `RULES`' proviso recognizer at `nizam/corpus/segment.py` only accepts a line starting literally with `Provided`; unlike the explanation and section rules it does not consume `_AMEND_PREFIX`. Thus `3[Provided` and `10[Provided` become continuation text (docs 118, 956). Add a narrowly guarded amendment-marker-prefixed proviso recognizer, retain the marker as provenance, and test against actual footnotes and enacted amendment text.
2. `segment`'s numbered-list handling assumes a dotted integer is section-like unless other narrow signals disprove it. Once the third proviso has been recognized, an explicit list context (“the following provisions ... as mentioned hereunder”) plus source indentation and consecutive local labels can attach items 1–3 beneath that proviso. “In section 2” is an amendment reference to another Act; it does not determine this Act's citation parent. Do not broadly reparent every “In section” opener: those can be genuine top-level amending sections elsewhere.
3. `_FOOTNOTE` recognizes “This Act was assented/published” but not the source-verified “This Act was passed by...” note on doc 118 page 2. A source-position/footnote-rule guard and precise provenance phrase are needed before excluding that block; a global “This Act was” rule could swallow operative text.
4. The repeated-label collision pass currently compares siblings only after the above parent context has already been lost. Do **not** change it to demote every later occurrence of 2; preserve both operative passages. Existing `source_reparent_blocks` override is exact-block-anchored but cannot alone create the absent third-proviso node or clean the footnote.

These are proposed code changes, **not an applied parser patch**. A shared grammar change would affect released documents, including up to 998 bracketed-proviso leads; applying it without a corpus dry-run and signed stored-tree comparison would violate the no-regression requirement. The source-backed expectation tests are deliberately `xfail(strict=True)` until a bounded patch passes.

All three currently **xfail**, exposing the known parser defects. The selected fixture blocks use the exact extracted source text and coordinates. A read-only current-parser reparse of docs 118 and 956 plus comparison docs 500 and 1000 exactly matched their stored trees (tree, S7 and TOC in all four). This proves reproducibility of the existing state, **not** correctness or safety of a proposed parser change. Dry-run output: [current-parser-dryrun.jsonl](../.artifacts/structural-audit-2026-09-23/current-parser-dryrun.jsonl).

The audit has **not** inspected every flagged PDF page or resolved all categories A–L. In particular, amendment reprints, cross-page continuation, Roman/alphabetic/mixed labels, marginal-note and TOC promotion, and embedded-instrument spans require targeted source review beyond the two verified PDFs. The screen is corpus-wide for *active stored nodes*; source verification is not corpus-wide, inactive historical revisions are out of scope, and the corpus cannot be called error-free. Next: deduplicate/prioritize the 64,922 flags, issue real source-anchored review IDs for new defects, verify high-risk pages against PDFs, implement narrow parser fixes, and run source-backed regression plus stored-tree comparisons over **every affected and previously released instrument** before any replay.
